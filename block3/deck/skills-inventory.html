06

General precedence notes

Picking rules Lecture
Rules · which skill wins

How to choose between overlapping skills

  • Repo-local beats global. Prefer repository-local skills over generic global skills when both apply to the same task.
  • Narrow beats broad. Prefer narrower skills over broader skills. Use the accessibility, metadata, PR monitoring, or validation-planning skills when the request is specifically about those areas.
  • Right tool, right system. Use bd/beads skills for beads issue workflows and GitHub issue skills for GitHub-native issue workflows.
  • Prefer the swe: namespace. Use SWE-prefixed skills for disciplined software-engineering workflows when available.
Speaker notes

"These four rules collapse to one heuristic: pick the smallest skill that fits the job. Workspace-local before global, narrow before broad, native-system before generic, curated-namespace before ad-hoc. If you remember nothing else from this page, remember that ordering."

Anchor: "This is why agentic engineering looks different from vibe coding. Vibe coding picks the most powerful tool. Agentic engineering picks the most precise tool."
